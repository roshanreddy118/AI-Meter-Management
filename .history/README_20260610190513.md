# Meter Tracker - AI Tenant Manager

A modern web app to track meter readings, calculate bills, and manage payment status for your rental properties using Neon Postgres.

## Features

- 📊 Add and manage multiple properties
- 📈 Track monthly meter readings (current - previous = units consumed)
- 💰 Automatic bill calculation (units × BESCOM rate)
- 📸 Attach meter reading photos
- ✅ Mark payments as pending/paid
- ⚙️ Update BESCOM rate anytime
- 📱 Fully responsive design with glowing UI
- 💾 All data persisted in Neon Postgres (survives deployments)

## Data Storage

Everything is saved permanently in **Neon Postgres**:
- All property details
- Complete history of meter readings (every month)
- Bill amounts calculated for each month
- Payment status for each bill
- All photos attached to readings
- Your BESCOM rate settings

**Neon Benefits:**
- Serverless PostgreSQL (scales automatically)
- Free tier covers your needs
- Can pause when not in use
- Better performance than traditional databases
- Easy to manage from https://console.neon.tech

## Tech Stack

- **Frontend**: Next.js 14 + React
- **Backend**: Next.js API Routes
- **Database**: Neon Postgres (serverless)
- **Hosting**: Vercel

## Local Development

1. **Clone and install**:
   ```bash
   npm install
   ```

2. **Set up Neon database**:
   - Go to https://console.neon.tech
   - Create a new project named "meter-tracker"
   - Copy the connection string
   - Create `.env.local` file:
     ```
     DATABASE_URL=postgresql://user:password@host/meter-tracker
     ```

3. **Run locally**:
   ```bash
   npm run dev
   ```
   Open http://localhost:3000

## Database Initialization

After deployment to Vercel, **you must initialize the database once** by visiting the init endpoint:

```
https://your-project.vercel.app/api/init
```

This will create all three tables:
- `properties` - stores your property information
- `meter_readings` - stores all meter readings and bills
- `settings` - stores your BESCOM rate (default: 8.5)

**What to expect:**
- You'll see a JSON response with success message
- All tables will be created automatically
- Default BESCOM rate of 8.5 will be set
- Then refresh your app - it will work normally

### Alternatively (Local Development)

Run the initialization script:
```bash
node scripts/init-db.js
```

## Deployment to Vercel

### Step 1: Push to GitHub
```bash
git add .
git commit -m "Update to Neon Postgres"
git push origin main
```

### Step 2: Deploy to Vercel
1. Go to [vercel.com](https://vercel.com)
2. Click "New Project"
3. Import your "AI-Meter-Management" repository
4. Click "Deploy"

### Step 3: Add Neon Database Connection
1. In Vercel dashboard, go to your project
2. Click "Settings" → "Environment Variables"
3. Add `DATABASE_URL` with your Neon connection string
4. Redeploy from "Deployments" tab

### Step 4: Done!
- Your app is live at `https://your-project.vercel.app`
- All data persists in Neon Postgres
- Database automatically scales with your needs

## How to Use

### Adding a Property
1. Click "+ Add Property"
2. Enter property name and address
3. Click "Add Property"

### Adding a Meter Reading
1. Click on a property card
2. Click "+ Add Reading"
3. Enter:
   - Reading date
   - Current meter reading value
   - (Optional) Photo of meter
4. System automatically:
   - Calculates units consumed (current - previous reading)
   - Calculates bill (units × BESCOM rate)
   - Shows pending payment status

### Updating BESCOM Rate
1. Click "⚙️ Settings"
2. Enter new rate per unit
3. New readings will use this rate

### Marking Payments
1. Open a property
2. In the readings table, change status from "Pending" to "Paid"

## API Endpoints

- `GET /api/properties` - Get all properties
- `POST /api/properties` - Add property
- `DELETE /api/properties?id=X` - Delete property
- `GET /api/readings?propertyId=X` - Get readings for property
- `POST /api/readings` - Add meter reading
- `PATCH /api/readings?id=X&action=payment` - Update payment status
- `GET /api/settings` - Get BESCOM rate
- `PATCH /api/settings` - Update BESCOM rate

## Troubleshooting

**Readings not saving?**
- Check if `DATABASE_URL` is set in Vercel environment variables
- Verify Neon database is active in console.neon.tech
- Check browser console for errors

**Can't connect to database locally?**
- Ensure `.env.local` has correct `DATABASE_URL`
- Test connection: `psql $DATABASE_URL`
- Check Neon console for connection limits

**Need to reset data?**
- Go to Neon console → SQL Editor
- Run: `DROP TABLE IF EXISTS meter_readings; DROP TABLE IF EXISTS properties; DROP TABLE IF EXISTS settings;`
- Restart app to recreate tables
